OpenBB não é Bloomberg.
E nenhum dos dois é uma Ontology.

A oportunidade para o Zoen não é recriar um terminal. É juntar quatro competências que hoje vivem separadas: federação de dados, identidade financeira, mundo operacional e autoridade causal.

O que “standard” realmente faz

  • alinha nomes e tipos compartilhados;
  • injeta parâmetros comuns + extras;
  • produz schemas transparentes;

O que permanece implícito

  • identidade econômica e venue;
  • currency, timezone, calendar e adjustment;
  • vintage/as-of e autoridade do provider;
  • raw digest, licença, entitlement e reconciliação.

Fallback, não ranking

Provider explícito vence; senão vale default/prioridade gerada e o primeiro cujas credentials existem. Uptime, custo, latency, freshness e quality não pontuam.

OBBject é attribution

Result, provider, warnings, chart e extra; invocation metadata e metadata do provider são opcionais. Não há raw digest/license/entitlement/lineage graph obrigatório.

Três MCPs, três boundaries

ODP MCP deriva FastAPI; Workspace MCP é serviço hospedado documentado e sem source público; Rita é bridge PoC in-memory. Não transferir guarantees entre eles.

MCP progressivo

A extensão deriva tools do FastAPI, comprime schema, cria índice categórico e deixa tools desabilitadas para ativação por sessão. Excelente defesa do context window.

Workspace context

Widgets e parâmetros sincronizados preservam a sessão analítica. Agent Rita transforma tabelas em SQLite e texto em prompt.

Citation ≠ lineage

Widget + input args explica “de onde veio a análise”. Não reconstrói necessariamente cada linha/célula do raw payload ou uma decisão operacional.

Security boundary do código aberto.

ODP core tem um global HTTP Basic e hook para auth extension; credentials são provider-scoped em settings locais/env. Workspace Enterprise anuncia RBAC/audit/export/retention, mas a implementação não estava pública: claims de produto não viraram guarantees auditáveis neste snapshot.

A ilha semanticamente mais forte está no provider SEC.

Ali aparecem 1.190 tags/namespace → 250 line items, 15 anos de taxonomias, proveniência por valor/período, distinção direct/imputed/corrected/reconciled/reconstructed, identidades contábeis e corpus de 970 históricos. Semântica profunda nasceu de uma vertical com regras e validação — não do envelope genérico.

06 / Bloomberg

O terminal é a superfície. O moat é o sistema de dados.

A documentação pública permite observar contratos e escala; não expõe toda a arquitetura interna do Terminal.

70M+instrumentos
40k+campos
8k+datasets
100B+data points / dia

Security master

FIGI é opaco, permanente e não reutilizado. O unified model público liga legal entities, securities, markets e prices.

Field contracts

BLPAPI Services/Operations expõem schemas de request/response em runtime. Data License entrega conteúdo em arquivos, REST e cloud.

Entitlements

Services têm autorização para operações restritas; DL+ governa acesso, seleção de campos e refresh.

Uma historical request é uma política

Date range, calendar, currency, non-trading fill, periodicity, max points, price/yield e corporate-action adjustment mudam a resposta. adjustmentFollowDPDF=true delega ajuste aos defaults do Terminal e ignora flags explícitas. (security, field, date) não é reproduzível.

Field ID + definition snapshot

FieldInfoRequest pode devolver unique ID, mnemonic, datatype, documentation, category, overrides e field type. HTTP 200 ainda pode conter response/security/field errors aninhados: status de transporte não é status semântico.

Aberto

FIGI, metadata básica, regras de alocação e especificação OMG podem formar uma ponte de identidade comum.

Licenciado

Preços, referência, fundamentais, estimates e outros facts têm termos, entitlements e direitos de redistribuição próprios.

HolderEconomicRight

Direito econômico do detentor — sentido de “entitlement” no FIBO.

DataAccessEntitlement

Autorização de user + service + EIDs para receber o dado.

ContractualUsageRight

Storage, display, derived use, model use, export e redistribution. Não deriva de um EID bem-sucedido.

FIBO ajuda a nomear

Issuer como role, instrument, listing com tempos e currency, ticker reassociável no contexto de exchange, pricing source e observed time.

FIBO não entrega a operação

Não fornece instances autoritativas, alocação FIGI, alias history, facts licenciados ou query semantics. Market Data e corporate-actions detalhados ainda estavam provisional no snapshot 2026.

Conclusão segura.

Bloomberg resolve três problemas juntos: “o que é isto?”, “qual campo/fato foi pedido?” e “quem pode consumir/redistribuir?”. A evidência pública fala em rastrear dados a source files; ela não prova lineage universal por célula dentro do Terminal.

Os padrões sustentam significado explícito, IDs governados, eventos/timestamps distinguíveis, proveniência, qualidade e evolução controlada. Internal master ID, bitemporalidade completa, append-only, resolution receipt, provider entitlements e uma superfície única CLI/API/MCP/Eve são decisões informadas do Zoen — não exigências desses standards.

“Single authoritative source” não precisa apagar rivais.

Preserve assertions, publique uma ResolutionPolicy por finalidade e materialize um accepted view com receipt: selected claims, rivals, quality, rule revision e motivo. Isso atende melhor a auditabilidade sem fabricar consenso.

09 / Zoen audit

O kernel está certo. Quatro boundaries são P0.

Audit final em e34445c. Os P0 se agrupam em quatro boundaries: identity/integrity, series, source admission e accepted view/entitlement.

◎

Meaning published

canonical JSON + digest + revision + activation/evolution.

◫

Bitemporal evidence

valid time + observed at + server-stamped ingestion + knowledge cut.

⟲

Causal lineage

supporting, rival e computation dependencies nos resultados.

◇

Governed mutation

proposal, policy, approval, preview/state basis, commit.

⇢

Effect boundary

commit não é external effect; tentativa e reconciliação são duráveis.

#

Idempotence

operation ID + intent digest reproduzem o primeiro receipt.

⌁

Projection cut

Snapshot semantics + exact least-privilege projection role; authority write é rejeitado.

⊢

Human + workload

session door, tenant boundary, Cedar e delegation existem.

Gaps observáveis

P0 · correctness

Entity não prova Type

ByType infere membership pela presença de qualquer claim em relation cujo source_type coincide.

P0 · correctness

Link target não é verificado

RelationTarget::Type(T) checa apenas se o value é Entity — não se a entidade é T.

P0 · belief

Latest ≠ true

Para cardinality one no state basis, o helper seleciona o maior supporting commit. Autoridade/qualidade não entram na decisão.

P0 · scale

Sem series plane

Cada scalar claim recebe commit/outbox; o projector v1 relê tudo e produz snapshot Parquet completo.

P0 · security

Write provenance não está bound

RecordEvidence autentica sessão/tenant, mas o caminho genérico não avalia Cedar nem liga a source declarada ao caller.

P0 · entitlement

Read policy depois da query

A query/paginação encontra candidates antes da policy por entity. Faltam field/source/purpose controls e paginação livre de side-channel.

P0 · identity

Sem security master

Não existem assignments de identificadores, candidates, context, merge/split ou supersession.

P1 · object view

Attributes declarativos

TypeDefinition não materializa ainda um objeto com required properties e typed links verificáveis.

P1 · object sets

Sem query algebra

Não há filtros, ordering, aggregation, reverse traversal, set algebra ou saved views pinados a revision/cut/policy.

P1 · action shape

Um proposal, um resource

Effects declarativos escrevem scalars no mesmo resource. Scenario já empacota proposals atomicamente, mas ainda não é um Action multi-subject first-class.

P1 · surfaces

MCP inbound não existe

O CLI registry é estático; a trilha MCP executável é hoje um source/client connector, não tools do Ontology.

P2 · source

Vertical ainda demo

O fluxo atual guarda CAS e signals, mas mapeia resources hard-coded via source.mapQuantity.

o scale trap

10.000 listings × 252 dias × 10 anos × 6 campos = 151.200.000 scalar claims

≤ 1.000claims por request batch

A matemática usa apenas OHLCV diário. Intraday, quotes, fundamentals e revisions multiplicam a ordem de grandeza. Nuance: effects de uma Action e de um Scenario compartilham o commit da operação; o problema 1:1 é do ingresso direto. A query atual é point-in-time e um instant só casa no timestamp exato; não existe contrato nativo de latest/range/downsample.
