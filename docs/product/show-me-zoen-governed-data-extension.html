03 / release é arquitetura

Quatro catálogos. Nunca um quinto.

A release congela significado executável, não o estado do mundo. Novos preços, membros ou grants não exigem uma nova release.

ontology_digest

OntologyCatalog

types, properties, interfaces, typed links, Actions, functions, fields, series definitions e SourceDefinitions.

policy_digest

PolicyCatalog

Cedar, source admission, resolution, quality, purpose, budgets e entitlement definitions.

WorldRelease contentid = SHA-256(JCS)
world_id · parent_digest
O · P · E · C
executor_digest

ExecutorCatalog

provider, broker, messaging e machine capability contracts; secret slots, nunca secrets.

component_digest

ComponentCatalog

normalizers, mappings, calendars, adjustments, computations e Wasm digests.

Publicação fica fora do conteúdo: WorldReleasePublication guarda release, published_at, published_by e PolicyEvidence. Um ponteiro transacional mantém somente uma release ativa por World. O bootstrap do primeiro owner roda uma vez e não cria superuser.
ProviderCapability é um contrato composto: shape e source no OntologyCatalog · acesso/resolução/rights no PolicyCatalog · chamada no ExecutorCatalog · código e mapper no ComponentCatalog.
result / cursor / proposal / receipt = WorldRelease × authority_data_cut × caller_context
04 / mundo semântico

Ticker é evidência. Objeto é identidade governada.

A identidade de acesso de uma pessoa e a identidade de um instrumento financeiro são problemas diferentes.

LegalEntityIBM Corp · LEI · CIK
→
Instrumentequity / debt / derivative
→
ShareClassglobal class identity
→
Listingvenue + currency + interval
→
VenueMIC · calendar · timezone

ObjectKey + TypedObjectRef<T>

ObjectKey é estável. TypeAssignment é explícita e não nasce da presença numa relation.

  • provider ID nunca é chave canônica
  • assignments carregam fonte e validade
  • links exigem assignments dos dois endpoints durante todo o intervalo

Evidence graph

Cada alegação mantém supporting, rival, provenance, raw digest e dependencies.

  • não sobrescreve restatement
  • não perde discordância
  • não promove “latest” a verdade

Accepted view

Uma derivação reproduzível para uma finalidade, release e cut. Não é uma autoridade paralela.

  • KnowledgeBasisDefinition publicada
  • ResolutionDecision durável por digest
  • CommitReceipt continua separado

O pack financeiro torna quatro relógios explícitos

01 · identity

Valid time

Quando ticker, listing, alias ou relação eram válidos.

02 · economics

Observation time

Instant ou período econômico ao qual o valor se refere.

03 · event

Lifecycle time

Announcement, ex, record, pay e effective time.

04 · knowledge

Knowledge cut

O que o World podia saber, com quais artifacts, naquele corte.

ObjectView<T> = selected properties + rivals + typed links + lineage + series refs + allowed Actions

O ObjectView carrega a base epistemológica da resposta. O ObjectSet é somente o plano lazy e autorizado que produz essas views.

06 / envelope de segurança

Permissão é uma interseção, não um filtro tardio.

Delivery entitlement e direito contratual de uso permanecem conceitos diferentes, mesmo quando avaliados pelo mesmo policy engine.

Membership ∩ object/property policy ∩ source/field/series entitlement ∩ purpose/usage right ∩ release = visible capability

A mesma interseção limita nomes de tools, schemas, existência de objetos, páginas, valores, lineage, citations, exportação e Actions.

× query → policy

Nunca buscar e paginar antes de autorizar o plano.

× credential → truth

Uma chave válida permite adquirir; não permite declarar realidade.

× endpoint ontology

Rotas de provider não viram types, links ou Actions do domínio.

× one cell = claim

OHLCV denso entra em segmentos; DatasetVersionAcceptance registra a aceitação do manifest.

× latest = accepted

Recência não resolve rival evidence nem restatement.

× manual MCP

Tools são geradas da release e filtradas pela autoridade do caller.

× projection = authority

Parquet e índices são descartáveis e reconstruíveis.

× commit = success

Commit registra intenção autorizada; efeito externo exige reconcile.

  • um WorldKernel e sete verbos
  • WorldRelease com quatro catálogos

  • entitlements antes de discovery e scan
  • OpenBB clean-room; AGPL exige decisão separada
  • IBM cobre FIN-01 até FIN-09
