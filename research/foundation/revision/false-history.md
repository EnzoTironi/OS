# Naive migrations that create false historical claims

**Kind:** counterexample  
**Decision:** each scenario is a falsifier for "schema migration preserves meaning." None is an OS design.  
**Related in-repo scenario:** `scenarios/README.md` S-012, ontology revision after a historical discount action.

A false historical claim is a later answer that a competent reader would take as "this is what was true or decided then" when the system has lost or replaced that meaning.

## FH-1. In-place rename of a collapsed date field

**Setup.** Revision R stores one property `deliveryDate`. In the business it mixed requested, promised, and actual dates. See `docs/open-questions.md` caution on collapsed date fields. Revision S renames the column to `actualDeliveryDate` and backfills by copying the old values.

**Naive migration.** `ALTER ... RENAME` or Alembic autogenerate as drop plus add with a copy.

**False claim.** "On 12 March we recorded the actual delivery date as 18 August."

**What was true.** Many of those values were promises or requests. The identifier change attached a new meaning to old numbers.

**Which law it attacks.** L3, L4, L7.

**Source pressure.** Alembic cannot detect rename and emits add plus drop (E-D2). Protobuf would treat this as a new field number only if the number changed. A name-only change on JSON storage is a semantic replacement.

## FH-2. Property ID change deletes writeback history, then current state looks original

**Setup.** A Palantir object type has writeback. Users edited `priority` for a year. An author changes the property ID from `priority` to `severity` because the label in the UI already says Severity.

**Naive migration.** Save the ID change. Phonograph refuses reindex (`InvalidColumnFieldSchemaChange`) until someone unregisters and reregisters. History of edits is deleted (E-P5). Writeback later builds from the backing dataset plus an empty edit log.

**False claim.** "These objects were never user-edited. The dataset values are the operational history."

**What was true.** A year of Action-driven edits existed and was the reconstruction path for writeback.

**Which law it attacks.** L1 if the old history is not snapshotted. L4.

## FH-3. Storage-engine move without preserve-history

**Setup.** OSv1 to OSv2 migration with preserve-history off (E-P6). Action Logs were enabled with default fields only (E-P7).

**Naive migration.** Acknowledge the dialog. After soak, OSv1 cannot be restored.

**False claim.** "The current object is the full record of what operators did." Action Log lists primary keys and an incrementing action-type version, so a dashboard can still show that *an* action occurred.

**What was true.** Intermediate property values and the function body behind each increment are gone unless stored elsewhere.

**Which law it attacks.** L2, L4.

## FH-4. Upcast, then persist, then audit

**Setup.** Event `DiscountGranted { orderId, percent }` is stored for years. A new handler wants `DiscountGranted { orderId, amount, currency }`. An upcaster computes `amount` from `percent` and today's price list. Someone "cleans up" by rewriting the event store to the new shape.

**Naive migration.** Treat Axon read-time conversion as a one-time storage rewrite.

**False claim.** "The original event recorded a 12.50 EUR discount."

**What was true.** The original event recorded 10 percent. The euro figure used a price list that did not exist at grant time.

**Which law it attacks.** L6. Axon 5.3 keeps stored bytes and converts at handling time (E-E1). Persisting the conversion destroys explain-replay.

## FH-5. Reused stable identifier, old bytes, new meaning

**Setup.** Protobuf field number 4 was `optional string customer_ref`. It is deleted. A year later field 4 is `optional string tax_id`. Old messages still carry field 4.

**Naive migration.** Skip `reserved 4` (E-A2).

**False claim.** "Historical invoices store a tax id."

**What was true.** Those bytes are customer references. The parser has no way to know.

**Which law it attacks.** L3. The same failure happens if an ontology reuses an action name, property id, or type id for a new concept.

## FH-6. Autogenerated drop-and-add presented as rename

**Setup.** Column `unit_cost` is renamed to `standard_cost` in the ORM. Alembic autogenerate emits drop `unit_cost` and add `standard_cost` (E-D2). An agent applies the file.

**Naive migration.** Trust autogenerate because `alembic check` wanted a revision.

**False claim.** After deploy, every historical cost is null or default. Reports say "we had no standard cost before this quarter."

**What was true.** `unit_cost` held the values. The migration deleted them.

**Which law it attacks.** L8, L4.

## FH-7. Split a name, drop the original, reconstruct as if composition were identity

**Setup.** GraphQL and the database replace `User.name` with `firstName` and `lastName`. A backfill splits on the first space. The old field is removed after usage drops (E-A3).

**Naive migration.** Later, an auditor asks for the name as submitted on the employment contract.

**False claim.** `firstName + " " + lastName` equals the historical legal name.

**What was true.** Some names had multiple given names, prefixes, or a chosen display name that was not a split of the legal name. The function is not invertible.

**Which law it attacks.** L4, L6. GraphQL's own guidance to migrate data first is necessary and still not sufficient if the transform loses information.

## FH-8. Policy body changes, action name does not

**Setup.** S-012. Version 1 of `ApplyDiscount` allows 15 percent for a named region. An action is approved and executed. Version 2 tightens the function to 5 percent and keeps the same action API name. Palantir-style function checks pass if the signature is unchanged (E-P8). Action Log stores action-type version 37 (E-P7) but not the function text.

**Naive migration.** Years later, replay `ApplyDiscount` against the order under current functions to "verify" the old approval.

**False claim.** "The 15 percent discount was never legal, so the old approval was an error." Or the opposite, if the new rule is looser: "The old approval already used today's rule."

**What was true.** The discount was legal under revision 1. Explain-replay needed that function body.

**Which law it attacks.** L2, L6, L7. This is the issue's central scenario.

## FH-9. Flyway undo after a destructive data step

**Setup.** Versioned migration drops `legacy_status`, after a backfill into `status`. Undo script adds `legacy_status` back as a nullable column (E-D3).

**Naive migration.** `flyway undo` after someone notices the backfill mapped `CLOSED` and `CANCELLED` onto one `status` value.

**False claim.** "We rolled back. Historical closed versus cancelled is restored."

**What was true.** The distinction lived only in the dropped column. Undo cannot invent it.

**Which law it attacks.** L4. ObjectStack ADR-0027 says the same: restore of dropped data is surfaced, not auto-run (E-O2).

## FH-10. SemVer minor that changes authorization

**Setup.** A function adds no parameters and changes a default threshold used in a policy. Publisher ships `1.4.0` because signature checks are green (E-P8, E-A1). Consumers accept `>=1.2.0 <2.0.0`.

**Naive migration.** Range install. Historical dashboards call the new function when explaining old actions.

**False claim.** "All 1.x discounts used a 5 percent cap."

**What was true.** 1.3.x used 15 percent. SemVer communicated "compatible" because the declared API was the signature.

**Which law it attacks.** L7. SemVer as a sufficient ontology model is `rejected`.

## FH-11. Default temporal query sold as audit

**Setup.** A late correction changes Mike's address valid-from September, recorded in August (E-T1). A report uses the default "as best known" query for "what address did we print on the August letter?"

**Naive migration.** None. This is a query-mode error that a schema migration can also trigger if it rewrites valid-time in place.

**False claim.** "On 20 August we knew the Bank Street address."

**What was true.** On 20 August, system-time still said London Road. Bank Street was scheduled, not yet valid, and the letter used London Road.

**Which law it attacks.** L6. Ontology analog: querying current definitions for a past action.

## FH-12. Dual versions without a contract phase

**Setup.** Fowler expand adds `Coordinate` methods beside `x,y` methods and dual-writes both stores (E-D1). The contract phase is never scheduled.

**Naive migration.** Six months later, some writers hit only the old store. A report reads only the new store.

**False claim.** "The grid is empty at (3,4)."

**What was true.** Cells exist in the old array. Coexistence without contraction is not a stable history. It is two competing histories.

**Which law it attacks.** L5 as a complete pattern. Expand without contract is `rejected` as an end state.

## How to use these later

A synthesis agent should turn each FH into an acceptance probe:

1. Perform the naive migration.
2. Ask the historical question in the scenario.
3. Fail if the system answers with the false claim and has no remaining artifact that contradicts it.

If a candidate OS revision model cannot represent the distinction the false claim erases, the model is not ready.
