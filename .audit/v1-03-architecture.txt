Caller usage

OIDC bearer token -> TrustedExecutionContext
Discover(definition, resource) -> visible Action capabilities
Propose(definition, action, resource, inputs, valid_at, operation_id) -> ActionProposal
Approve(proposal, approval_id, expires_at) -> ActionApproval
Commit(proposal, operation_id) -> CommitOutcome

Chosen shape

zoen-core owns branded identity, validated delegation chains, Action proposal states, policy evidence, StateBasis dependencies, and commit receipts. It has no IO or vendor dependencies.

zoen-engine owns one ActionEngine. The engine validates definitions and business inputs, checks delegation, evaluates policy through PolicyEvaluator, reads dependencies through QueryExecutor, and sends one CommitPlan through AuthorityStore.

zoen-query implements QueryExecutor with strong semantic queries. StateBasis contains only dependencies that the Action precondition evaluated.

zoen-adapters implements PolicyEvaluator with Cedar and extends PostgresAuthorityStore for durable proposals, approvals, operation receipts, and atomic Action commits. Action commits append to authority_commits and projection_outbox.

zoend validates OIDC issuer, audience, signature, and expiry. It constructs TrustedExecutionContext and adapts Connect messages. Action requests do not accept a tenant, actor, principal, or workload field.

Candidate assessment

Candidate A puts the complete lifecycle in ActionEngine behind the existing deep ports. It keeps transport, Cedar, and SQL private to their assigned boundaries. Chosen.

Candidate B coordinates query, Cedar, and SQL in zoend. Rejected because transport code would own Action semantics and callers would depend on execution order.

Candidate C adds Action, Cedar, and OIDC crates. Rejected because it recreates technology-owned shallow modules that ADR-0014 already ruled out.

Data model

TrustedExecutionContext contains TenantId, ActorId, PrincipalId, WorkloadId, and one validated DelegationChain.

DelegationChain is a nonempty ordered set of grants. Every child grant must be a subset of its parent for Action, resource, workload, and time.

PolicyEvaluation is Permit, Deny, or EvaluationError. Permit and Deny carry the exact policy revision and determining policy IDs.

ActionProposal is either Ready or AwaitingApproval. Both states pin the definition, canonical intent digest, operation identity, policy evidence, and StateBasis.

StateBasis is a sorted set of material claim dependencies plus its digest. Global authority revision is explanatory metadata only.

CommitPlan binds one stored proposal, one operation identity, effects, and the expected StateBasis. PostgreSQL rechecks the relevant dependencies inside the commit transaction before it appends semantic records.
